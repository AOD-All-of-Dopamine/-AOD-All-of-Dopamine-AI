# 사전 등록 h67 — "모두에게 좋은" 후보를 직접 검색한다

작성 시점: h66 판정 봉인 직후(`ca7ccda4d43066818826377044ad8ea9`), **어떤 신규 검색도 하기 전.**

## 0. 왜 이것인가

h66 이 남긴 질문:

> `적합_전체` 를 통과하려면 **"모두에게 좋은"(세 항목 모두 등급 ≥2)** 후보가 필요한데
> 풀의 **10.0%** 뿐이고, 코사인 max 는 그 10% 를 골라내지 못한다.
> 오라클 **56.7%** vs 실제 **26.7%**.

그런데 h66 은 **max 로 만든 풀 안에서 재정렬만** 했다. 등록 §5 에 이렇게 적어 뒀다:

> **진짜 min 기반 검색은 이 배치가 답하지 않는다.**

**이 배치가 그것을 답한다.** 두 갈래가 있다:

- **(가) 코퍼스에 "모두에게 좋은" 후보가 있는데 max 검색이 못 찾는다** ⇒ 검색을 바꾸면 된다.
- **(나) 그런 후보 자체가 드물다** ⇒ 검색을 바꿔도 소용없다. `적합_전체` 는 이 코퍼스에서
  달성 불가에 가깝고, **목표를 `적합_max` 로 확정해야 한다.**

**어느 쪽이든 결론이 명확해진다.** 그래서 이 배치는 빗나가도 값이 있다.

## 1. 검색 방법 — 지금 고정한다

후보 c 와 프로필 3항목 p₁,p₂,p₃ 에 대해, 허브니스 보정(λ=0.35) 코사인을 `cos(pᵢ,c)` 라 하자.

| 코드 | 질의 | 성격 |
|---|---|---|
| **R-max** | `max_i cos(pᵢ,c)` | **현행** (기저선) |
| **R-min** | `min_i cos(pᵢ,c)` | 세 항목 **모두**와 가까운 후보 — "모두에게 좋은"의 직역 |
| **R-cent** | `cos(centroid(p₁,p₂,p₃), c)` | 프로필 중심 벡터 단일 질의 |

세 가지 외에는 시도하지 않는다. 가중 평균·임계 조합 등은 **추가하지 않는다.**

## 2. 표본 — 신규 채점이 필요하다

- 시드: h62 의 **10개 그대로**(프로필 동일). ⇒ R-max 결과는 **h62 채점을 재사용**한다.
- R-min · R-cent 각각 **도메인별 상위 2건** ⇒ 시드당 12건, 전체 **120건**.
- 성인 필터·TMDB 한국어 필터·이름 기준 프로필 제외(D-15) 모두 h62 와 동일.
- 이미 채점된 (기준작품, 후보) 조합은 **재사용**하고, 신규만 채점한다.

## 3. 예측

- **P1 (1차)** R-min 이 R-max 보다 **`적합_전체` 통과율이 2σ 이상 높다.**
  σ 는 **같은 선택 규칙(도메인별 top-1, 3칸)으로 무작위 2,000회**를 돌려 구한다(D-16).
  절차만 지금 고정하고 값은 계산이 정한다. **관측 후 조정하지 않는다.**

- **P2 (기제 · 1차와 독립)** R-min 이 가져온 후보 중 **"모두에게 좋음"(세 항목 모두 ≥2)**
  비율이 **20.0% 이상**이다.
  - 기저선은 h62 의 max 기반 풀에서 관측된 **10.0%** 다. **2배**를 구조적 경계로 미리 정한다.
  - **P1 과 P2 를 나눈 이유**: P1 은 3칸 표본이라 잡음이 크고, P2 는 후보 수준이라 민감하다.
    **P2 가 적중하고 P1 이 빗나가면 "기제는 작동하나 표본이 작다"**로 기록한다.

- **P3 (예상되는 대가 · 기각 조건 없음)** R-min 의 `적합_max` 는 R-max 보다 **낮을 것이다.**
  얼마나 낮은지를 보고한다. h66 에서 재정렬만으로도 93.3% → 70.0% 였다.

- **P4 (기술 통계)** R-cent 의 같은 값들 · 세 방법이 가져온 후보의 **겹침** ·
  등급 모양 분포(모두 좋음 / 전문가 / 모두 무난 / 혼합) · 채택 지표 **F** 로도 병기.

## 4. 판정 규칙 — 미리 못 박는다

| 결과 | 결론 |
|---|---|
| P1·P2 둘 다 적중 | **(가)** — 검색이 문제였다. R-min 방향으로 간다 |
| P2 만 적중 | 기제는 작동. 표본을 키워 재확인해야 한다 |
| P1 만 적중 | **의심한다** — 기제 없이 통과율만 오른 것은 잡음일 수 있다. 재현 필요 |
| 둘 다 빗나감 | **(나)** — 코퍼스에 그런 후보가 드물다. **목표를 `적합_max` 로 확정**하고 `적합_전체` 추구를 접는다 |

## 5. 절차

- 채점은 **눈가림**, 3/2/1/0, 전문 사용(D-10), ID 셔플(D-11).
- **모든 신규 쌍이 채점되기 전에는 어떤 집계도 계산하지 않는다.**
- 검색 결과를 **보고 나서** 방법을 추가하거나 k 를 바꾸지 않는다.
- 배치 간 절대 비교 금지(D-14). 대비는 **같은 시드 안에서만.**

## 6. 한계

- **R-min 은 임베딩 안에서의 "모두에게 좋음"이다.** 사람이 매기는 등급과 같지 않을 수 있고,
  그 간극이 바로 이 배치가 재는 것이다.
- 도메인별 top-2 는 얕다. h62 가 보였듯 깊은 구간에도 좋은 후보가 있다.
  **R-min 의 깊은 구간은 이 배치가 답하지 않는다.**
- 시드 10개 · 3칸 선택이라 P1 의 표본 오차가 크다(그래서 P2 를 따로 걸었다).
- `적합_전체` 는 D-17 대상 — **`적합_전체 ÷ 적합_max` 를 함께 보고**한다.
- 등급이 전부 내 것이다(D-6) · 실유저 없음(D-3).
  **(나) 로 결론이 나도 "사용자가 `적합_전체` 를 원하지 않는다"는 뜻은 아니다.**
  **"우리 코퍼스와 표현으로는 못 준다"는 뜻이다.**
