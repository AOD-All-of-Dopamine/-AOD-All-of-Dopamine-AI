# 표현 층 계획 — 순위 11~50 의 붕괴를 잡는다 (2026-08-29)

## 목표와 판정 잣대
- 목표: 페르소나 v2(32) 에서 **P@50 ≥ 0.80** (독립 3인 다수결, §59 잣대). 단 **P@10 이 0.85 아래로 떨어지면 안 된다** — 첫 페이지를 팔아 꼬리를 사는 건 안 한다.
- 현재: P@10 0.872 · P@50 0.724. 플랫폼 순위 31-50 이 Steam 0.68 · TMDB 0.67 · 웹소설 0.57.
- 원칙 그대로: 사전등록 → md5 봉인 → 눈가림 채점 → 판정. 한 번에 한 축. **dev/val 분리**: 무작위 60 = dev(조율), 페르소나 v2 = val(판정). 페르소나로 조율하지 않는다.

## 환경 제약 (실측)
GPU 없음. Steam 173,691편 재임베딩은 CPU 로 하루 이상(과거 34회 분할). 웹소설 7,062편은 1~2시간, TMDB 59,780편은 반나절. 리랭커(크로스 인코더)는 요청당 후보 100쌍이면 CPU 에서 수 초 — 서빙엔 캐시가 필요하지만 평가엔 문제없다.

## 0단계 — 진단: 꼬리가 무너지는 이유가 "후보 부재"인가 "순서 오류"인가 (반나절)
순위 51~100 에 적합한 항목이 있는지 잰다. 있으면 **재정렬(1단계)** 로 닿고, 없으면 **표현 자체(2단계)** 를 바꿔야 한다.
- 페르소나 v2 중 P@50 미달 12개, 플랫폼별 top-100 에서 순위 51-100 을 10개씩 표본 → 360 슬롯, 3 역할 채점 (18 에이전트).
- 지표: 51-100 적합률. 판정(관측 전 고정): **≥ 0.60 이면 1단계로**, < 0.40 이면 1단계를 건너뛰고 2단계로. 사이면 둘 다.
- 예상: Steam 0.55, TMDB 0.45, 웹소설 0.40 — 플랫폼마다 갈릴 것.

## 1단계 — 리랭커: 임베딩 top-100 을 크로스 인코더로 재정렬 (2~3일)
- 모델: 다국어 크로스 인코더 `BAAI/bge-reranker-v2-m3` (CPU 가능, 한국어 지원). 로컬에 없으면 받는다 — 받을 수 없는 환경이면 `Qwen3-Embedding` 을 쓰는 대안(시드 텍스트를 하나의 질의로 합쳐 재계산)으로 간다.
- 질의 = 시드들의 `semantic_text` 를 이어 붙인 것 (플랫폼별), 문서 = 후보 `semantic_text`. 점수 = 리랭커 점수 **단독**(임베딩 점수와 섞지 않는다 — 스케일이 다르고 D-60/X-12 에서 섞기가 실패했다). 각 플랫폼 top-100 → top-50 으로 자른다.
- 변형은 하나만: 시드 결합 방식 {이어붙이기 / 시드별 최대}. dev(무작위 60)에서 고르고 val 에서 판정.
- 판정: val P@50 **+0.05 이상**이고 P@10 −0.02 이내면 채택. 부작용: 대작 반복(ILS), 시드 속편 재유입 — 후처리(D-46 drop_seed_iter, franchise cap)는 리랭커 뒤에 그대로 건다.
- 비용: 페르소나 32 × 3 플랫폼 × 100 쌍 = 9,600 쌍 추론(CPU 30분 내). 채점은 바뀐 슬롯만(≈400) → 21 에이전트.
- 예상: P@50 +0.04~0.08. TMDB 가 가장 많이 오르고 웹소설은 후보 부재라 덜 오를 것.

## 2단계 — 표현 교체: 임베딩 텍스트에 구조화된 취향 신호를 넣는다 (플랫폼별 1~3일)
현재 텍스트는 "줄거리 위주"라 임베딩이 **소재**(귀신·우주·천재)를 잡고 **결**(톤·독자층·서브장르)을 놓친다(§64 의 제목 어휘 추종).
- 순서: **웹소설 먼저**(7k, 가장 싸고 가장 나쁨) → TMDB → Steam(태그가 없는데 태그가 D-49 에서 신호였다).
- 새 텍스트 = `[장르] [서브장르 태그 K개] [핵심 소재 K개] 제목 · 줄거리 앞 N자`. 서브장르 태그는 (a) 있는 메타(Steam tags, TMDB keywords)에서, (b) 없는 웹소설은 **LLM 이 시놉시스에서 뽑은 태그 5개**(서브에이전트 배치, 7k 편 → 120 에이전트, 한 번만). 태그 사전은 코퍼스 피복 문서의 하위 장르 목록에서 시작한다.
- 재임베딩: 같은 `Qwen3-Embedding-0.6B`, 같은 파이프라인(`embed_qwen.py`). 모델을 바꾸지 않는다 — 텍스트만 바꿔야 원인을 분리할 수 있다.
- 판정: 플랫폼별 슬롯 P@50(val) **+0.05**, P@10 유지. 웹소설이 오르면 TMDB·Steam 으로 확장, 안 오르면 여기서 멈추고 1단계 결과로 간다.
- 위험: 재임베딩하면 단일 플랫폼 확정값(quality_w, genre_w, pop_boost…)의 최적점이 움직일 수 있다 — 그 재조율은 **하지 않는다**(같은 값으로 전후 비교). 좋아지면 그때 별건으로 연다.

## 3단계 — 결합과 노출 정책 (반나절)
1·2 를 둘 다 채택했으면 결합(재표현 임베딩 top-100 → 리랭커)을 한 번 더 val 로 잰다. 그래도 P@50 < 0.80 이면 **노출 k 를 P@k ≥ 0.80 인 최대 k 로 정한다**(현재 추정 k≈20~30). 이건 성능이 아니라 정책이고, 그렇게 적는다.

## 하지 않는 것
- 페르소나·시드 조정, 판정 문턱 사후 변경, 임베딩 모델 교체(변인 분리 불가), 플랫폼 확정값 재조율(별건).
- 서빙 시 LLM 리랭킹 — 평가엔 쓸 수 있지만 제품 지연·비용이 맞지 않는다. 필요하면 "상한 측정"으로만 한 번 잰다.
