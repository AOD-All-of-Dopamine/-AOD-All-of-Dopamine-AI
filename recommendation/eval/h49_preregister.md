# 사전 등록 h49 — fun_tag 의 유효성과 **크로스 플랫폼 고유성**

작성 시점: h48 판정 직후(md5 `ab9883cd15b9621e4641f4dfe1e837b7`), 도메인 내 검색 실행 **전**.

## 왜 두 부분인가

목표는 "fun_tag 이 **크로스 플랫폼** 추천에 도움이 되는가"다. h48 은 웹소설→Steam
한 방향만 쟀으므로, 설령 fun_tag 이 도움이 된다 해도 그것이

  (a) 도메인과 무관하게 좋은 랭킹 feature 라서인지
  (b) **도메인을 건널 때 임베딩이 잃어버리는 것을 fun_tag 이 메우기 때문**인지

를 가를 수 없다. (b) 여야만 "크로스 플랫폼의 근거"가 된다. 그래서 **도메인 내 대조군**이
필요하다. 이것이 이 프로젝트의 존립 질문이며, 지금껏 한 번도 측정된 적이 없다.

# A. h48 재판정 — 가드 교정 (채점 0건)

## 무엇을 고치는가
h48 의 H5 는 *"중앙값(AUC_sim) > 0.5 이고 p<0.05, 아니면 배치 무효"* 였다.
전제는 "검색이 무신호면 하류가 전부 잡음"이었으나, 실제 데이터는 **sim 은 약하고
fun_tag 은 강한** 형태였다. 후보 풀이 약해도 그 안에서 fun_tag 이 좋은 것을 위로
올린다면 그것은 실재하는 결과다. 가드가 잘못 설계됐다.

## 교정된 가드 (S1)
**S1**: 미리 고정된 네 점수 `{sim, ft, E, J}` 중 **적어도 하나**의 시드별 AUC 중앙값이
0.5보다 유의하게 크다. 다중비교를 위해 **본페로니 보정 α = 0.05/4 = 0.0125**.
→ 빗나가면 등급이 어떤 사전 지정 신호와도 무관하다는 뜻이므로 배치 무효.

이 가드는 "어느 신호가 이기는가"를 전제하지 않는다. h48 의 H5 는 sim 이 이겨야만
통과하는, 가설과 얽힌 가드였다.

## 재판정할 예측 (h48 원문 그대로, 기준 불변)
- **H1** 중앙값(AUC_E − AUC_sim) ≥ +0.05, p<0.05
- **H2** 중앙값(AUC_ft) ≥ 0.55, 0.5 대비 p<0.05
- **H3** 적합후보 보유율: 게이트 통과 − 탈락 ≥ 20%p

## ⚠ 이것은 회고 분석이다
데이터를 이미 봤다. 13차에서 회고 채택이 14차 신규 시드에서 무너진 전례가 있다.
**A 가 전부 적중해도 '채택'이 아니라 'B 에서 확증 대상'으로만 올린다.**
기준을 바꾸지 않고 가드만 교정했다는 점을 근거로 삼되, 그 이상 주장하지 않는다.

# B. 크로스 플랫폼 고유성 — 도메인 내 대조군

## 설계
h48 의 **신규 20시드를 그대로** 쓴다(웹소설 시드). 같은 시드로

  · 교차: 웹소설 → Steam   (h48 에서 이미 채점 완료, 200쌍)
  · **내부: 웹소설 → 웹소설** (신규. 시드 자신은 제외, top-10)

를 만들고, **동일한 절차**로 라벨링(220건)·눈가림 채점(200건)한다.
파이프라인·허브니스 λ=0.35·전문 사용·14축 모두 h48 과 동일하게 맞춘다.

## 주 지표
시드마다 두 조건 각각에서 `AUC_ft − AUC_sim` (= fun_tag 이 유사도 위에 더한 양)을 구하고,
**같은 시드에서 교차 − 내부** 의 차이에 부호순위 검정.

    Δ_cross(seed) = AUC_ft(교차) − AUC_sim(교차)
    Δ_within(seed) = AUC_ft(내부) − AUC_sim(내부)
    검정 대상 = Δ_cross − Δ_within

## 예측
- **X1 (핵심)** 중앙값(Δ_cross − Δ_within) **≥ +0.10** 이고 p < 0.05.
  → **fun_tag 의 이득이 도메인을 건널 때 특별히 크다** = 크로스 플랫폼의 근거.
  → 빗나가면 **"fun_tag 이 크로스 플랫폼을 가능하게 한다"는 주장을 철회**하고,
    fun_tag 을 일반 랭킹 feature 로 재분류한다(그 경우에도 A 가 적중했다면 유용하긴 하다).

- **X2 (임베딩 열화 확인)** 중앙값(AUC_sim 내부) − 중앙값(AUC_sim 교차) **≥ +0.10**.
  → 임베딩이 도메인을 건널 때 실제로 나빠진다는 직접 증거. X1 의 메커니즘 설명.
  → 빗나가면 X1 이 적중해도 "왜 그런지"는 설명되지 않은 채로 둔다.

- **X3 (건전성)** S1 과 동일한 가드를 내부 조건에도 적용.
  → 빗나가면 내부 조건 무효, X1·X2 해석 금지.

- **X4 (기술 통계, 기각 조건 없음)** 교차·내부 각각의 top-1 적합률을 A/B/C/E 갈래로 보고.

## 절차
- 40시드(교차 20 + 내부 20) 채점이 끝나기 전에는 어떤 집계도 계산하지 않는다.
- 라벨은 채점 전에 확정하고 md5 를 남긴다.
- 내부 검색에서 **시드 자신과 동일 작품(제목 접두 일치)은 제외**한다.
- 한계: 채점자 = 라벨러(D-6). 결과를 상한으로 읽는다.

## B 가 답하지 못하는 것
Steam 이라는 **한 target 도메인**만 본다. TMDB 로의 일반화는 별도(h50)다.
