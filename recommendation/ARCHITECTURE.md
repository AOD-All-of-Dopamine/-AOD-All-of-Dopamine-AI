# AOD 통합 추천 아키텍처 — 검토용 (2026-08-31 갱신, 코드 기준)

> 남에게 설명할 개요·다이어그램은 `OVERVIEW.md` 를 보세요. 이 문서는 결정 근거와 열린 결함을 따지는 검토용입니다.

Steam · TMDB · 웹소설 세 랭커가 각자 순위를 내고, 통합 층은 **순위만** 받아 쿼터로 섞는다.

## 1. 전체 모양

| | Steam | TMDB | 웹소설 |
|---|---|---|---|
| 텍스트 | 설명 + 태그15 + 장르 + 모드 (제목 제외) | 줄거리 + 키워드15 + 장르 (제목 제외) | 제목 + 장르 + 줄거리 (제목 포함) |
| 검색 | 시드별 질의 · 허브 보정 λ 0.35 | 시드별 질의 · λ 0.35 · 한글 줄거리만 | 시드별 질의 · 허브 보정 없음 |
| 결합 | top2_mean | mean | top2_mean |
| 점수 | sim × (1 + 품질·태그·메타크리틱) | sim × (1+평점) × (1+장르피복) × (1−매체불일치) | sim × (1 + 0.03·인기백분위) |
| 후처리 | 성인·VR·출시전 제거, 시리즈 1 · 퍼블리셔 2, 시드 속편 제거, 시드별 교차 | 프랜차이즈 1 · 시드 프랜차이즈 0, 시드 속편 제거, 시드별 교차 | 19금 제거, 시드 시리즈 제거, 시리즈 1 · 작가 2, 시드별 교차 |

↓ 각 플랫폼 top-50 (순위만) ↓

**통합 층 M6** — 플랫폼별 쿼터 라운드로빈. 시드가 1개뿐인 플랫폼은 가중 0.5, 웹소설은 20화 미만 제거, 목록이 마르면 빈 자리로 둔다(채워 넣지 않음). 점수는 절대 섞지 않는다.

세 플랫폼이 같은 임베딩 모델을 쓰지만 **벡터를 합치거나 게이팅하지 않는다.** 통합은 오직 순위 위에서만 일어난다.

> **왜 이 모양인가.** 초기 실험에서 게이팅(어느 플랫폼을 보여줄지 학습) 50.0% · 쿼터 51.7% · 무작위 49.1% 로 게이팅이 무작위와 구별되지 않았고, 도메인별 top-2 가 전역 top-6 보다 +5.0pp 좋았다 (`crossdomain/DESIGN.md` §8). 시드를 한 벡터로 합치면 응집도 낮은 프로필이 무너지는 현상이 세 플랫폼에서 재현됐다 (D-22). 세 랭커의 점수 스케일이 서로 다른 것도 순위만 쓰는 이유다.

> **검토 포인트.** 게이팅 실험은 h58 시점(초기 코퍼스·초기 채점)의 결과다. 지금의 독립 3역할 채점으로 다시 재면 결론이 같을지는 검증되지 않았다. 다만 "게이팅 없음"은 단순성 이득이 커서, 재검증 비용 대비 뒤집힐 가능성은 낮게 본다.

## 2. 표현 — 무엇을 임베딩하나

**Steam** (`steam/src/text_builder.py:115`)
```
Description: {short_description}
Tags: {상위 15개 태그, 득표순}
Genres: {genres}
Modes: {categories 중 플랫폼 기능 잡음 제거}
```
**제목·판매 순위는 뺀다.** 제목을 넣으면 같은 프랜차이즈끼리 뭉친다.

**TMDB** (`tmdb/src/text_builder.py:26`, `candidate_retriever.py:40`)
```
줄거리: {overview}   ← 한글 우선, 없으면 영어
키워드: {keywords[:15]}
장르: {genres}
```
같은 이유로 제목 제외. 서빙 때는 **한글 줄거리가 있는 33,728편만** 내보낸다 — 영어만 있는 26,052편은 인덱스에는 있지만 추천되지 않는다.

**웹소설** (`webnovel/src/text_builder.py:37`)
```
제목: {name}
장르: {genres}
줄거리: {synopsis}
```
**여기는 제목을 넣는다.** 웹소설 제목은 로그라인("회귀한 천재 검사는…")이라 정보량이 크다. 인기·평점·댓글 수는 제외.

진행 중인 **wn_v5** 는 이 텍스트를 `장르 | 태그(규칙 34개 중 ≤5) / 제목 / 줄거리[:600]` 로 바꾼 것이다. R-0 진단에서 웹소설 51-100위 적합률이 0.35 로 "후보 자체가 없다" 판정이 났기 때문이다 (`webnovel/src/wn_tags.py`, `eval/r2wn_preregister.md`).

> **검토 포인트.** ① 임베딩 모델은 코퍼스 문장에 *지시문 없이*, 질의(앵커)에만 지시문을 붙인다 — 그런데 추천 경로는 시드 *아이템의 코퍼스 벡터*를 질의로 쓰므로 지시문은 실제 서빙에 관여하지 않는다. ② TMDB 는 한글 줄거리 유무가 곧 "추천 가능" 조건이다 — 코퍼스의 44% 가 조용히 빠진다. 이게 의도인지 확인이 필요하다.

## 3. 검색 — 시드에서 후보로

세 플랫폼 모두 같은 뼈대다. **시드마다 별도의 질의 벡터**를 만들고(평균 안 냄), 코퍼스 전체와 정확 내적을 한 뒤, 시드×후보 행렬을 후보 단위로 접는다.

```
score(seed, cand) = ⟨ seed − λ·centroid , cand ⟩      # 허브 보정, λ = 0.35 (Steam·TMDB), 0 (웹소설)
결합:  top2_mean = 후보별 상위 2개 시드 유사도의 평균 (시드 ≤2 이면 그냥 평균)   # Steam·웹소설
       mean      = 모든 시드 평균                                                # TMDB
dominant_seed = argmax_seed  → 후처리의 "시드별 교차"에 쓰임
```

| 결정 | 내용 | 측정치 |
|---|---|---|
| 허브 보정 λ 0.35 | 코퍼스 중심을 빼서 어디에나 가까운 "허브" 항목을 누른다. Steam 에서 모든 축을 동시에 올린 유일한 레버 | k=75 에서 +0.018 [+0.007, +0.029] |
| D-22 시드 미합산 | 시드 평균 벡터는 취향이 갈리는 프로필을 망친다 | 하위 8개 프로필이 모두 응집도 0.45–0.67 |
| D-20 행 인덱스 시드 | TMDB 는 제목 중복이 8.8%(5,269행) 라 이름으로 시드를 잡으면 안 된다 | — |
| 검색 깊이 | Steam `top_n×5`, TMDB `top_n×8`, 웹소설 `k×8` 을 뽑아 후처리로 깎는다 | — |

> **검토 포인트.** 웹소설만 허브 보정이 0 이다. 코퍼스가 7천 건이라 허브 현상이 약하다는 게 이유인데, 별도 측정 기록은 못 찾았다(D-번호 없음). wn_v5 로 표현을 바꾼 뒤 한 번 재야 한다. 또 결합 전략이 플랫폼마다 다른데(top2_mean vs mean) 각자 그 플랫폼에서 이긴 값이지, 통합 관점에서 맞춰 본 적은 없다.

## 4. 정렬 — 유사도에 무엇을 곱하나

세 플랫폼 모두 `final = similarity × (1 + 보정)` 꼴이고, 보정 항은 전부 **사전등록 → 채점 → 판정**을 거쳐 채택되거나 기각됐다. 확정값은 각 플랫폼 `src/config.py` 의 `PRODUCTION` 한 곳에 있다 (D-55).

### Steam (`personalized_ranker.py:193`)
```
boost = 0.03·리뷰수 백분위          # rec_boost — 사실상 무효 (리뷰 수 87.4% 결측)
      + 0.50·quality                 # quality = clip(log10(1+리뷰수)/5, 0, 1)      D-38, D-50/51
      + 0.40·tag_fit                 # tag_fit = max_i |후보태그 ∩ 시드_i 태그| / |시드_i 태그|   D-49
      + 0.20·[메타크리틱 있음]        # 점수가 아니라 '있음'                          D-56
final = sim × (1 + boost)
```

| 항 | 왜 | 측정치 |
|---|---|---|
| quality_w 0.50 | 저품질 롱테일이 상위를 침범(D-33). 로그 리뷰 수가 신호 | 0.00→0.464 · **0.50→0.769**; 양쪽 스윕 0.40 0.826 · 0.50 0.835 · 0.70 0.832 |
| tag_w 0.40 | 20위 아래 유사도가 평평(20위 0.489 → 50위 0.483). 태그 피복이 꼬리를 가른다 | dev 0.793→0.835 · val 0.739→0.803 |
| mc_w 0.20 | "격" 축 — 메타크리틱 *존재*가 점수보다 잔차 상관이 높다 | 존재 +0.131 vs 점수 +0.060 |
| rec_boost 0.03 | 세 곳에 세 값(0/0.03/0.15)으로 갈라져 있던 걸 통일(D-73). 효과는 없음 | 0~5.0 스윕에서 top-50 동일 |

### TMDB (`personalized_ranker.py:88`)
```
base  = 1 + 0.15·rating_norm                       # rating_norm = clip((평점−5)/5, −1, 1)   D-31
base *= 1 + 0.40·genre_fit                          # genre_fit = max_i |A∩S_i|/|S_i|         D-44
base *= 1 − 0.20·[매체 ≠ 시드 매체 집합]              # 영화 시드 → TV 는 소프트 감점            D-42
final = sim × base                                  # vote_w 0 (D-60·X-12 기각), align_w 0 (미확정)
```

| 항 | 왜 | 측정치 |
|---|---|---|
| genre_w 0.40 | 자카드(D-43)는 후보의 *추가* 장르를 벌줘서 기각. 시드별 최대 피복으로 바꿈 | val 0.882→0.917 · 대상군 0.830→0.870 |
| media_w 0.20 | 하드 필터 대신 소프트 감점 | 영화 시드→TV 적합 0.764 vs 0.877 |
| vote_w 0 (기각) | 인기 부스트는 대작 취향엔 좋고 롱테일엔 해롭다. X-12 에서 다시 시험 | TMDB 슬롯 −0.021 · 롱테일 4개 프로필 < −0.10 |

### 웹소설 (`wn_eval.py:127`)
```
final = sim × (1 + 0.03·인기 백분위)               # pop_boost D-66 · rating_boost 0 (D-62: 신호 없음)
```
웹소설은 품질 신호를 하나도 못 찾았다. 관심 수 <100 슬롯 적합 0.961 vs ≥100 0.958, 로그 관심수 잔차 −0.006 (D-62). MMR 다양화는 전역(D-53)·버킷(D-54) 둘 다 기각 — 전역 MMR 은 오히려 ILS 를 올리고 시드 피복을 반으로 줄였다.

> **검토 포인트.** ① Steam·TMDB 의 보정 항은 전부 *인기/품질/메타데이터 정합*이다. 임베딩 유사도가 top-50 안에서 변별력이 없다는 게 R-0/X-13 의 결론이라, 이 항들은 "유사도가 못 가르는 구간을 무엇으로 채우나"의 답이다. 그게 취향 적합의 대리인지, 그냥 안전한 유명작 선호인지는 통합 P@50 0.72 가 말해 준다 — 아직 부족하다. ② 웹소설은 보정할 축이 없어서 표현 자체를 바꾸는 중(wn_v5). ③ TMDB `align_w` 는 D-42/43 당시 켜져 있다고 믿었지만 실제로는 꺼져 있었다(`tmdb/src/config.py:20`). D-43 판정은 그 레버 없이 잰 것이다.

## 6. 통합 — M6 (`crossdomain/mix.py:94`)

```
lists = _wnfilter(lists, episodes, 20)                 # 웹소설 20화 미만 제거 (통합 층에서만)   X-2, X-4
plats = 시드 수 내림차순, 동률이면 steam → tmdb → wn
w     = {p: 0.5 if 시드 1개 else 1.0}                   # X-10
q     = 쿼터: max(1, round(k·w[p]/Σw)), 합이 k 넘으면 큰 쪽부터 −1
return 라운드로빈으로 각 플랫폼 목록을 위에서부터 q[p] 개씩 — 목록이 마르면 빈 칸   D-23
```
예: k=10, 시드 {steam 1, tmdb 3, wn 2} → 쿼터 {steam 2, tmdb 4, wn 4}.

| 단계 | 왜 | 통합 P@50 (무작위 60) |
|---|---|---|
| M0 기준선 | 균등 라운드로빈. 시드 비례(M1 +0.011)·응집도 가중(M2 +0.015)은 문턱 미달로 기각 | 0.833 (당시 채점) |
| M3 20화 필터 | 웹소설이 범인: 같은 항목이 단독 0.93 → 통합 0.67. 10화 이하가 top-50 의 35.7%(D-35). 10/20/30/50 스윕에서 20 유지 | 0.833 → 0.893 · wn 0.670 → 0.862 |
| M6 단일 시드 0.5 | 독립 3역할 채점 600 슬롯에서 시드 1개 플랫폼 슬롯 P 0.42 vs 나머지 0.84 | 0.803 → 0.820 (+0.017) · 대상 17개 0.706 → 0.765 |
| M7 투표 <100 필터 | 기각 — 빠진 TMDB 슬롯 대신 들어온 것도 0.72 라 제자리 | −0.006 |

> **검토 포인트.** ① "안 채운다"(D-23)와 "쿼터 재분배"(M6)는 다른 상황이다 — 전자는 목록이 마를 때, 후자는 시드가 1개일 때. 헷갈리기 쉬운데 코드는 구분한다. ② 응집도(coh)는 M2 기각 뒤로 M6 에서 *안 쓴다*. 응집도 ≥0.7 다중 시드 프로필도 P 가 0.25~1.00 으로 흩어져 신호가 아니었다. ③ 20화 필터는 *통합 층에서만* 걸린다 — 단독 웹소설 추천엔 안 걸린다. 이 비대칭이 의도인지.

## 7. 서빙 흐름 (시험대)

```
브라우저 → :8000 gateway.py ─┬→ :8011 steam backend    (AOD_ARTIFACTS=tags_full, PRODUCTION, top2_mean)
                            ├→ :8012 tmdb backend     (tmdb_v1, PRODUCTION + PRODUCTION_POSTPROCESS)
                            └→ :8013 webnovel backend (wn_v4, Engine 기본값 = PRODUCTION)
통합:  seed_index.json 에서 시드 → 플랫폼별 /recommend?k=50 → 카드 stat 문자열에서 "N화" 파싱 → M6 → 카드 조립
채점:  POST /grade → eval/user_grades.jsonl (설계자 채점 은행과 분리 — D-25 의 유일한 독립 증거)
```
각 백엔드는 모델 + 코퍼스 임베딩을 메모리에 올린다(각 2~3.5GB). 이 세션은 **cgroup 6GB 상한**이라 백엔드 3개와 임베딩 작업을 동시에 못 돌린다 — 2026-08-30 프로세스가 두 번 죽은 원인.

## 8. 평가 방법 — 숫자를 믿어도 되는가

- **채점자 = 설계자** 문제(D-25). 단독 플랫폼 채점 은행은 독립 채점보다 0.14~0.2 관대했다(은행 0.940 vs 독립 0.743). 그래서 은행의 절대값은 버리고 **독립 3역할 눈가림 다수결**(평가자·헤비유저·편집자, 만장일치 ~83%)을 표준 잣대로 삼았다 (X-8/9).
- **사전등록**: 가설·문턱·대상군을 관측 전에 md5 로 봉인. X-5 의 M5 는 +0.016 으로 문턱 +0.02 에 0.004 모자랐고 *문턱을 옮기지 않았다*.
- **dev/val 분리**: dev = 무작위 60 프로필, val = 페르소나 v2 32(사람이 검수한 조합). 한 번에 한 축만 옮긴다.
- **P@k 의 한계**: 웹소설에서 적합률과 목록 내 유사도(ILS) 상관이 +0.308 — 같은 걸 열 개 보여 주면 점수가 *오른다*. ILS 를 같이 본다(D-32).

| 현재 성적 (독립 채점) | P@10 | P@50 | 플랫폼별 P@50 |
|---|---|---|---|
| 무작위 60 · M6 | 0.88 | 0.820 ± 0.03 | — |
| 페르소나 v2 32 · M6 + Steam 리랭커 (현행) | **0.872** | **0.785** | Steam 0.935 · TMDB 0.776 |
| 페르소나 v2 32 · M6 | 0.872 | **0.724 (목표 0.80)** | Steam 0.860 · TMDB 0.741 · 웹소설 0.733 |
| R-0 51-100위 적합률 | — | — | Steam 0.49 · TMDB 0.53 · 웹소설 0.35 |

R-0 의 뜻: Steam·TMDB 는 51-100위에도 적합작이 반이나 있다 → 후보는 있는데 *순서*가 틀렸다 → 리랭커(R-1). 웹소설은 0.35 → 후보 자체가 없다 → 표현을 바꾼다(R-2wn, 진행 중).
