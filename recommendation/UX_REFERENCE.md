# UX 레퍼런스 — 통합 발견 서비스는 어떻게 만들어졌나 (2026-09-24)

우리 서비스는 **5개 도메인(게임·영화·시리즈·웹툰·웹소설)을 한 곳에 모아 발견·결정을 돕고, 소비는 외부 플랫폼에서 일어나는** 구조다.
같은 구조로 성공한 서비스 24개를 조사해, **우리가 베낄 것과 베낄 수 없는 것**을 갈랐다.

- 문제 현황은 `CURRENT_ISSUES.md`, 추천 탭의 구체적 수정 계획은 `REC_TAB_DESIGN.md` §2-8·§2-9.
- 이 문서는 **왜 그렇게 고치는지**를 담는다. 출처는 각 항목에 붙였다.

---

## 0. 먼저 정한 것 — 목표와 지표

"오래 머무르게 한다"와 "외부 링크로 내보낸다"는 충돌한다. 통합 서비스는 소비를 소유하지 않으므로,
우리가 잡을 수 있는 체류는 **소비 시간이 아니라 결정 시간**이다. 목표를 이렇게 쓴다:

> 흩어진 5개 플랫폼을 **비교·결정하는 한 곳**이 되고, 결정 이후에도 **돌아올 이유**를 만든다.

| 지표 | 뜻 |
|---|---|
| 세션당 비교한 작품 수 | 발견이 실제로 일어났나 |
| **7일 재방문률** | 돌아올 이유가 있나 |
| 축적 자산(좋아요·상태·책장) | 떠나기 어려운 이유가 쌓이나 |

**체류 시간 자체를 KPI 로 삼지 않는다** — 외부 링크에 마찰을 넣거나 숨기는 방향으로 흐르고, 그러면 통합 서비스의 존재 이유가 사라진다.

## 1. 사례에서 반복된 원칙 5개

### 1-1. "보는 중"은 모든 도메인에 필요한 게 아니다
- **Douban**: 도서는 `读过/在读/想读`, 영화는 `看过/想看`(**보는 중 없음**), TV 는 `在看` 있음. 2시간짜리는 중간 상태가 의미 없고 몇 주짜리는 필요하다는 논리. [zhihu 논의](https://www.zhihu.com/question/21456163)
- **Letterboxd**: 영화 전용이라 Watchlist/Watched **두 개뿐**. [FAQ](https://letterboxd.com/about/faq/)
- **Backloggd**(게임): Played/Completed/**Abandoned**/Retired/Shelved — "클리어"와 "포기"와 "무기한 중단"을 구분.
- **AniList**: Watching/Planning/Completed/Dropped/Paused/**Repeating** 6종.

→ **우리 결론**: 도메인마다 상태 모델을 달리한다. 영화 2단계 · TV·게임·웹툰·웹소설 3단계 + 하차.

### 1-2. 기록의 마찰을 평가에서 분리한다
- **Letterboxd**: 포스터 위 **눈동자 아이콘 1탭 = 봤음**(날짜·평점 불필요). 별점·리뷰는 별도 폼. [watched vs log](https://letterboxd.zendesk.com/hc/en-us/articles/15178778774543)
- **AniList**: 리스트 카드 호버의 **"+1"** 로 상세 진입 없이 진행도만 올림.
- 원리: "평가해 달라"고 하면 안 누르고, "봤다고만 찍어라"면 누른다.

### 1-3. 재방문은 알림이 아니라 "스케줄"에서 나온다
- **Trakt**: 개인 + 전역 방영 캘린더, 이메일 다이제스트, iCal. [VIP Calendars](https://trakt.tv/vip/calendars)
- **왓챠피디아**: 미개봉작을 "보고싶어요"에 넣으면 **D-day 카운트다운 + 개봉일 푸시**.
- **Steam**: 위시리스트 트리거 4종(정식 출시 · 얼리액세스→정식 · **20%+ 할인** · 데모 출시), 유저당 **1~2주 쿨다운**. [immutable 정리](https://www.immutable.com/insights/how-steam-notifies-wishlisters-at-launch)
- 공통 구조: **찜 → 날짜가 오면 되부름.**

### 1-4. "곧 사라진다"가 "새로 나왔다"보다 세다
- **키노라이츠**: "신작" 탭과 나란히 **"종료예정작" 탭**. Netflix 자체가 종료 예정을 안 알려준다는 점을 존재 이유로 삼음.
- **Reelgood**: 플랫폼별 이탈 예정작을 월별로 모은 `Leaving` 허브.
- 키노라이츠 CEO: *"대다수는 추천을 받기보다 다음 볼 콘텐츠를 '발견'하는 쪽에 가깝다"* [KOCCA 인터뷰](https://www.kocca.kr/trend/vol30/sub/s41.html)

### 1-5. 홈의 고정 순서는 지역 최적이다
- **Netflix**: *"A rule can specify that the first row will be 'Continue watching,' then 'New Releases,' then 'Top 10'... [but this] represented a local optimum"* [Learning a Personalized Homepage](https://medium.com/netflix-techblog/learning-a-personalized-homepage-aa8ec670359a)
- **Spotify**: 선반(shelf) 이름으로 이유를 밝히고, exploitation 과 exploration 을 함께 배치. [Spotify Engineering](https://engineering.atspotify.com/2020/1/for-your-ears-only-personalizing-spotify-home-with-machine-learning)
- **네이버웹툰**(2022 개편): **요일 전역 편성이 기본**, 그 안에 AI 추천을 요일당 1개만 끼움 — 개인 신호가 없어도 화면이 비지 않는 절충안.

→ **우리 결론**: 홈은 고정 템플릿이 아니라 **조건부 행**(있으면 뜨고 없으면 내려간다).

## 3. 화면별 적용안

### 3-1. 카드
지금은 하트 + ⋯ 메뉴뿐이다. 넣을 것:
```
[포스터]
제목 · "코코를 좋아해서"
[👍] [👎]              [봤어요 ✓]     ← 1탭 상태, 평점은 나중
```
- ⚠️ **이중 평가 혼란 주의**: 👍/👎(추천 신호)와 리뷰 별점(작품 평가)이 공존하면 "왜 두 번 평가하지?"로 읽힌다 — 키노라이츠가 이중 평점 시스템에서 실제로 겪은 문제다. 문구로 역할을 가른다(👍 = 이런 걸 더 보여줘 / 별점 = 작품 평가).

### 3-2. 상세
지금은 외부 링크에서 끝난다(§CURRENT_ISSUES 3번). 넣을 것:
1. **"어디서 볼까" — 내가 구독한 플랫폼 먼저.** Letterboxd Pro 의 "즐겨찾는 서비스", Apple TV 의 Single Sign-On, 키노라이츠의 "정액제만 보기"가 전부 같은 순서다.
2. 하단에 **"비슷한 작품" + "다른 분야에서 비슷한 것"** — 도메인을 넘는 추천은 우리만 할 수 있다.
3. 상세를 종착점이 아니라 **다음 루프의 입구**로. 왓챠피디아의 평가 → 필모그래피 → 재평가 순환, Apple TV 의 Up Next 자동 재삽입이 같은 설계다.

### 3-3. 홈 — 조건부 행
| 행 | 뜨는 조건 | 지금 가능? |
|---|---|---|
| 이어서 | 보는 중 1개 이상 | ❌ 상태 필요 |
| 오늘 연재 | 오늘 요일 작품 | ⚠️ 전역은 **지금 됨**(목요일 웹툰 140건), 개인화는 상태 필요 |
| 당신 취향 + [더 보기 →] | 시드 1개 이상 | ⚠️ 엔진 배포 후 |
| 놓친 신작 | 마지막 방문 이후 | ✅ (도메인 균형 필요 — 지금 `releases/recent` 상위는 웹소설이 독식) |
| 이번 주 인기 | 항상(폴백) | ✅ |

- 추천은 **홈의 한 줄**이고 `/for-you` 가 깊게 파는 면이다. 홈을 추천으로 덮으면 시드 0 사용자에게는 대체 목록 화면이 된다.
- 지금의 도메인별 슬라이드(`DomainRotator`)는 없애지 않고 **하단 또는 탐색 탭으로 내린다** — 도메인 선택은 탐색 성격이지 홈 상단의 일이 아니다.

### 3-4. 온보딩
- **왓챠피디아**는 신규 가입 시 **20개 평가**를 마쳐야 개인화가 열리고, 10/20/30 을 **A/B 로 측정해 20 을 골랐다**(너무 적으면 신호 부족, 많으면 완료 전 이탈). 노출 작품도 완료율을 높이려 큐레이션한다. [ZDNet 2013](https://zdnet.co.kr/view/?no=20131213103837)
- **Netflix** 는 반대로 선택 사항으로 두고 건너뛰면 인기·다양성 폴백을 준 뒤, 실제 시청이 초기 응답을 빠르게 덮어쓴다.
- **우리 현재**: "최소 3개, 분야마다 2개 이상" 안내(배포본 확인). 추천기가 시드 3개로 동작하니 숫자 자체는 타당하지만 **완료율·재방문을 재본 적이 없다.** 측정부터 붙인다.

## 4. 클릭의 의미를 가려내기 — 측정 설계

클릭 한 번에는 최소 네 가지가 섞여 있다: **취향 적합 · 표지의 흡인력 · 친숙함 · 위치.**
YouTube 가 2012년 조회수에서 시청 시간으로 목표를 옮긴 이유이고, Netflix 가 작품마다 사용자별로 다른 썸네일을 고르는 이유다 — 이미지만 바꿔도 클릭이 크게 변한다는 것은 **클릭의 상당 부분이 내용이 아니라 표지 때문**이라는 뜻이다.

"왜 눌렀나"는 물어서 알 수 없다. 세 가지 방법뿐이다.

**① 뒷단으로 검증한다 — 지금 로그로 바로 된다**
`impression_viewed → card_clicked → detail_viewed(visible_ms) → outbound_clicked` 가 모두 적재되므로:
```
표지 낚임률   = (클릭 후 상세 체류 < 3초) / 전체 클릭
결정 전환율   = outbound_clicked / card_clicked
망설임        = 노출 시간 상위인데 클릭 없음
```
같은 슬롯에서 **클릭률은 높은데 결정 전환율이 낮은 작품** = 표지가 이긴 경우다.

**② 친숙함을 기준선으로 뺀다 — 지금 된다**
"어디서 들어본 작품"은 곧 인기도다. 인기 백분위로 예측되는 클릭률을 기준선으로 깔고 **그 위에 남는 초과분**만 추천의 공로로 본다. 이걸 빼지 않으면 추천기가 "유명한 것만 올리는 장치"가 돼도 지표는 좋아 보인다 — Steam 꼬리 붕괴(EXPERIMENT_LOG D-33 계열)에서 이미 겪은 현상이다.

**③ 표지·제목·이유 문구는 실험으로만 갈린다**
썸네일은 우리가 만들지 않지만 **카드 구성은 우리 것**이다. 한 번에 하나만 바꾼다: 이유 문구 유무 · 평점/리뷰 수 표시 유무 · 포스터 크기. `rec_request` 에 실험 배정 칸이 이미 있다.

**가장 큰 오염원 — "이미 본 작품"**
친숙해서 누른 클릭 중 최악은 이미 소비한 작품이다. 사용자는 확인차 누르고, 로그에는 성공으로 남고, 추천기는 그것을 잘한 추천으로 배운다. **틀린 라벨이 쌓인다.**
지금 우리가 아는 것은 좋아요·북마크뿐이라 "볼 예정"과 "이미 봤음"을 구분하지 못한다.
→ **상태 3단계는 리텐션 기능이기 이전에 측정 위생 문제다.** Netflix 가 본 작품을 홈에서 빼는 것도 같은 이유다.

## 6. 권하는 순서

1. **상태 3단계(도메인별 차등) + 카드 1탭 로그** — 필드 하나로 시작된다. "이어서"도 추천 라벨 위생도 여기서 나온다
2. **"어디서 볼까" 개선** — OTT 이름은 이미 있으니 링크만(플랫폼 검색 URL 로 먼저)
3. **홈 조건부 행 + 오늘 연재(전역)** — 데이터가 이미 있어 추천 배포를 기다리지 않아도 된다
4. **클릭 질 지표 대시보드** — 추가 수집 없이 오늘 로그로 계산된다
5. **상세 "비슷한 작품"(도메인 교차)** — 엔진 배포 후
6. **캘린더/배지 → 알림** — 인프라가 생기면 Steam 식 트리거 4종 + 1~2주 쿨다운
7. **팔로우·활동 피드** — 컬렉션 공개/좋아요가 이미 있으니 그 위에

## 7. 피할 함정 (사례의 실패에서)

- **딥링크를 기능이 아니라 파이프라인으로 다룬다** — JustWatch 는 Trustpilot 2.2/5 에 *"90%는 어디서 스트리밍되는지 틀리다"* 는 혹평이 쌓여 있고, 키노라이츠도 "이용 가능"인데 죽은 링크 사례가 보고된다.
- **알림 남용** — 키노라이츠는 알림을 꺼도 광고성 푸시가 온다는 불만이 있다. Steam 의 1~2주 쿨다운이 좋은 기준선.
- **평점 조작은 도메인마다 유인이 다르다** — 왓챠피디아의 조직적 0.5점 테러, Steam 리뷰 폭탄(2019년부터 오프토픽 리뷰를 점수에서 제외). 키노라이츠는 **300편 이상 본 "인증회원"** 게이트로 방어한다. 5개 도메인을 한 화면에 섞을 때 게이트 설계는 도메인별로 따로 검토한다.
- **소셜 개편의 역풍** — 왓챠피디아는 2015년 SNS 형 피드 개편 후 반발로 2016년 알고리즘 추천 우선으로 되돌렸다. 소셜은 기존 동선을 밀어내지 않고 **옆에** 붙인다.
- **카탈로그 쏠림** — 우리 카탈로그는 게임 178,627 · 영화 22,030 · 웹소설 12,600 · 시리즈 10,511 · 웹툰 3,694 로 **게임이 79%** 다. 균형 규칙 없이 섞으면 통합 화면이 게임 목록이 된다.
