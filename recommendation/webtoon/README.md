# 웹툰 추천 (webtoon)

네이버 웹툰 정식 연재/완결 작품 대상 오프라인 배치 추천 파이프라인.
`webnovel/` 의 구조를 이식하고 도메인 술어만 교체했다. 네 번째 단일 플랫폼이다.

```
크롤 → 정제 → 표현 → 임베딩 → [표현 진단 게이트] → 검색·랭킹 → 후처리 → 판정
```

---

## 1. 자료원 — 왜 네이버 웹툰인가

`comic.naver.com` 의 **공개 JSON API**. 로그인·키 없이 열리고 HTML 파싱이 필요 없다.

| 항목 | 값 (2026-09-04 실측) |
|---|---|
| 연재 중 | 752편 (요일별 목록 7개, 중복 제거) |
| 완결 | 3,116편 (70페이지) |
| **고유 합계** | **3,868편** |

**도전만화·베스트도전은 넣지 않는다.** 정식 연재가 아니고 품질 분포가 완전히 달라
같은 코퍼스에 섞으면 랭킹이 무너진다(Steam 이 리뷰 미보고 롱테일에서 겪은 문제와 같은 모양).

**성인 웹툰은 상세 API 가 401 을 준다** — 웹소설 19금이 로그인 리다이렉트로 빠지던 것과 같다.
따로 거를 필요 없이 수집 단계에서 빠지고, `postprocess` 에서 한 번 더 막는다.

대안으로 검토한 **네이버 시리즈 "만화"** 는 단행본 만화 중심이라 "웹툰"이 아니고,
크롤 구조도 웹소설 판과 겹쳐 새로 얻는 것이 적다. 그래서 쓰지 않았다.

## 2. 웹소설 판과 무엇이 같고 무엇이 다른가

**같은 것** — 계약과 규율. 시드별 질의(평균 내지 않음) → 접기 → `유사도 × (1+보정)` 정렬 →
후처리(하드 필터 → 시리즈 상한 → 작가 상한 → 시드 교차 → Top-N) → `next_page()` 제외 집합,
그리고 **사전등록 → md5 봉인 → 눈가림 3역할 채점 → 미채점 0 → 판정**.

**다른 것** — 신호.

| | 웹소설 | 웹툰 |
|---|---|---|
| 인기도 | `interest_count` | **`favorite_count`** (관심 수) |
| 평점 | `rating` (신호 없었음 D-62) | **`star_score`** (10점, 미측정) |
| 장르 | 1개 coarse 라벨 | 1~2개 + **`tags` 10~12개** |
| 작가 | `author` 1명 | **글/그림 분리** (`artists`) |
| 연령 | `age_limit` 19 | `age_type` RATE_19 · `adult` |
| 시리즈 마커 | n부 · 외전 · 시즌n · [단행본] | 시즌n · n부 · 외전 · [리메이크] |
| 원작 링크 | 없음 | **`novelOriginAuthors`** (웹소설 원작 표시) |

**가장 큰 차이는 태그다.** 작품당 10~12개(`사이다`·`먼치킨`·`학원물`·`다크히어로`·`소설원작`…)로
Steam 태그에 가까운 밀도다. 그래서 두 곳에서 기회가 된다 —
표현(`semantic_text` 에 태그를 넣을지)과 정렬(Steam 의 태그 피복률 `tag_w` 형태).
**둘 다 아직 측정하지 않았다.**

## 3. 확정된 값 — **아직 없다**

`src/config.py` 의 `PRODUCTION` 은 전부 **웹소설에서 이식한 출발점**이고 웹툰에서 측정된 적이 없다.
값 옆에 D-번호가 없다는 것이 그 뜻이다. 순서는 이렇게 간다:

1. **표현 진단 게이트** (`src.diagnose_representation`) — 장르 변별력·유사도 평탄도·허브.
   rep_v1(제목+장르+줄거리) vs rep_v2(+태그)를 **재고 고른다.** 측정 전에 기본을 정하지 않는다.
2. 프로필 만들기 → 눈가림 3역할 채점으로 **기준선** 확보.
3. 축을 하나씩 사전등록으로 판정: `pop_boost` → `tag_w` → `strategy` → `hub_lambda` → `star_boost`.

**한 번에 하나만 옮긴다. 관측 후 문턱을 바꾸지 않는다. 점수를 위해 프로필을 조정하지 않는다.**

## 4. 쓰는 법

```bash
cd recommendation/webtoon
PYTHONPATH=. python -m src.crawl_naverwebtoon --out data/webtoons.jsonl --rps 2.5
PYTHONPATH=. python -m src.data_loader                 # 정제 → artifacts/wt_v1/dataset.parquet
PYTHONPATH=. python -m src.embed_qwen --rep v2         # 임베딩 (단독으로 돌린다)
PYTHONPATH=. python -m src.diagnose_representation     # 표현 진단 게이트
```

**메모리**: 임베딩은 백엔드·리랭커와 **같이 띄우지 않는다.** 과거에 그렇게 하다 cgroup 한계에서 죽었다.

## 5. 지금 상태 (2026-09-04)

| 단계 | 상태 |
|---|---|
| 크롤 | **완료** — 3,868편 열거 → **3,687편 수집** (성인물 181편은 상세가 401) |
| 정제 | **완료** — 3,687편 전부 통과 (성인·짧은 줄거리·비정식 제외 규칙에 걸린 것 없음) |
| 표현 | **완료** — rep_v1 / rep_v2 정의, 태그 정지어 규칙 확정 |
| 임베딩 | **진행 중** — CPU 전용(GPU 없음)이라 **장시간 작업**이다 |
| 프로필 | **완료** — 67개, 전부 기계 생성 |
| 파이프라인 | **연기 시험 통과** — 가짜 벡터로 검색·정렬·후처리·`next_page`·눈가림 시트·`score` 전 경로 확인 |
| 확정값 | **없음** — 아직 아무 축도 판정하지 않았다 |

### 코퍼스 실측
줄거리 중앙 **126자**(웹소설 482자의 1/4) · 태그 중앙 5개(p90 13) · 장르 1개 ·
관심 수 중앙 55,295 · 회차 중앙 64 · 완결 2,718편 · `semantic_text` 중앙 182자.
토큰 길이 중앙 147 · p99 361 → **`max_seq_length` 384** (0.8% 만 잘린다).

**줄거리가 얇다는 것이 웹툰의 가장 큰 표현 위험이다.** 그래서 태그를 넣은 rep_v2 를
기본 후보로 두되, 진단 게이트로 rep_v1 과 **비교해서 고른다.**

### 겪은 함정 세 가지 (전부 코드에 주석으로 남겼다)
1. **401 백오프** — 성인 웹툰의 401 은 레이트 제한이 아니라 영구 조건인데 지수 백오프로
   다뤘더니 성인물이 몰린 구간에서 지연이 5초까지 올라 처리량이 1/8 로 떨어졌다. 이제 건너뛴다.
2. **`max_seq_length` 미설정** — Qwen3 기본값 32768 로 돌리면 배치 1개에 5분 52초가 걸린다
   (전체 45시간). 384 로 제한한다.
3. **`완결*` 태그** — `완결로맨스`·`완결드라마`·`완결무료` … 가 태그의 **13%** 였다.
   장르를 중복하면서 연재 상태를 인코딩해, 두면 임베딩이 내용이 아니라 완결 여부로 뭉친다.

### 프로필 67개 — 전부 기계 생성인 이유
X-24(내가 지어낸 조합이 val 의 결함) · X-25(**응집된 시드일수록 P@50 이 높다**)의 교훈이다.
"같은 결"이라고 내가 골라 묶으면 그 자체로 점수가 부풀려진다. 그래서 시드 선택에
판단을 넣지 않고 **축을 설계**했다:

| 축 | 개수 | 뜻 |
|---|---|---|
| `rule_{장르}_{대역}` | 29 | 장르 × 관심 수 3구간, 무작위 3시드 — 인기 구간별 품질 차 |
| `coh_{장르}` | 10 | 한 장르 무작위 5시드 (응집) |
| `mix_{a}_{b}` | 12 | 두 장르에서 무작위 (혼합) |
| `k{n}_{장르}` | 16 | 시드 개수 1/3/5/10 — X-25 가 −0.103 을 본 축 |

`coh` vs `mix` 는 **X-25 의 다양성 발견이 웹툰에서도 재현되는지** 보는 대조쌍이다.

### 다음 순서
1. 임베딩 완료 → `src.diagnose_representation` 으로 **rep_v1 vs rep_v2 판정** (사전등록)
2. 이긴 표현으로 기준선 눈가림 3역할 채점 → P@10/P@50 + ILS
3. 축을 하나씩 사전등록으로: `pop_boost` → `tag_w` → `strategy` → `hub_lambda` → `star_boost`

## 6. 표현 진단 게이트 결과 (2026-09-04)

임베딩 완료: rep_v2(제목+장르+**태그**+줄거리) → `artifacts/wt_v1` · rep_v1(태그 없음) → `artifacts/rep_v1`.
각 3,687×1024. CPU 전용으로 2시간 57분.

### 코퍼스 수준 — 두 표현이 거의 같다

| | 장르 변별력 | 1위 | 10위 | 50위 | 낙차(10→50) | 허브 |
|---|---|---|---|---|---|---|
| 웹툰 rep_v2 | **+0.0825** | 0.665 | 0.600 | 0.562 | 0.0373 | 2편 |
| 웹툰 rep_v1 | +0.0782 | 0.656 | 0.591 | 0.554 | 0.0371 | 1편 |

참고로 다른 플랫폼(같은 방식):
웹소설 **+0.0778** (낙차 0.0392) · TMDB +0.0395 (0.0270) · Steam +0.0404 (0.0261).
**주의**: 장르 라벨 체계가 다르다 — 웹툰·웹소설은 coarse 1개, Steam·TMDB 는 다중 라벨이라
첫 번째만 썼다. **플랫폼 간 비교는 참고용**이고, 웹툰 두 표현끼리의 비교만 깨끗하다.

읽을 것: 웹툰의 꼬리는 Steam·TMDB 보다 **덜 평평하다**(낙차 0.037 vs 0.026).
Steam 이 보정 항에 의존하게 된 이유가 평평한 꼬리였으니, 웹툰은 그만큼 여유가 있다.

### 목록 수준 — 그런데 46% 가 다르다

같은 프로필 67개에서 두 표현의 top-50 겹침이 **중앙 54%**(최소 26% · 최대 88%)다.
**코퍼스 지표가 둔했다** — 변별력 차이가 0.004 인데 목록의 절반이 바뀐다.

### 태그가 무엇을 바꾸는가 — **게이트로는 결정할 수 없다**

객관 지표로는 갈리지 않는다 (프로필 67개 평균):

| | 제목 단어 겹침 | 시드 장르 일치 | ILS |
|---|---|---|---|
| rep_v2 (태그 O) | 2.0% | 78.6% | 0.544 |
| rep_v1 (태그 X) | 2.3% | 81.3% | 0.532 |

**정직하게 적는다.** 처음에 이웃 몇 개를 눈으로 보고 "rep_v1 이 제목 단어 매칭에 빠진다"고
읽었다 — `여신강림 → 행운의 여신` · `신의 탑 → 신을 죽이는 방법`. **전체로 재니 아니었다**
(2.3% vs 2.0%). 내가 고른 예시가 하필 흔한 단어(신·여신)를 가진 제목이었다. 선택 편향이다.

남는 차이는 rep_v1 이 장르 일치가 조금 높고(81.3 vs 78.6) ILS 가 조금 낮다는 것뿐인데,
그게 **더 정확한 것**인지 **더 좁은 것**인지는 이 지표들로 구분되지 않는다
(`참교육 → 비질란테` 는 액션→스릴러라 장르 불일치지만 결은 맞는다).

**결론: 표현 게이트는 "둘 다 망가지지 않았다"까지만 말한다.** 변별력·평탄도·허브 모두 정상이고
웹소설과 같은 수준이다. **어느 쪽이 나은지는 채점으로만 갈린다 — 사전등록 대상이다.**
게이트를 통과했으므로 랭커 단계로 넘어갈 수 있다.
