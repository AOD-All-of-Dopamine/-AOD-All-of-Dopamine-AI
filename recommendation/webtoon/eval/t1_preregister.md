# T-1 사전등록 — 웹툰 표현: rep_v1(제목+장르+줄거리) vs rep_v2(+태그) (2026-09-04)

웹툰 단일 플랫폼의 **첫 번째 축**이다. 확정값은 아직 하나도 없다.

## 왜
표현 진단 게이트(README §6)는 둘 다 정상이라고 했지만 **결정을 못 냈다** — 코퍼스 지표(변별력 +0.0825 vs
+0.0782)는 거의 같은데 top-50 의 **46%** 가 다르다. 객관 지표(제목 단어 겹침 2.0 vs 2.3% · 장르 일치
78.6 vs 81.3% · ILS 0.544 vs 0.532)로도 갈리지 않았다. 채점으로만 갈린다.

## 변형 — 표현만 다르고 나머지는 전부 같다
| 팔 | 임베딩 | 텍스트 |
|---|---|---|
| **rep_v1** | `artifacts/rep_v1` | 제목 + 장르 + 줄거리 (웹소설과 같은 모양) |
| **rep_v2** | `artifacts/wt_v1` | 제목 + 장르 + **태그** + 줄거리 (`완결*` 등 정지어 12종 제거) |

**보정 항은 전부 끈다** (`pop_boost=0 · star_boost=0 · tag_w=0 · hub_lambda=0`). 표현 비교에 보정이 끼면
차이가 보정에 가려진다. 접기 `top2_mean` · 후처리(성인 제외·시리즈 1·작가 2·시드 교차)는 둘 다 같다.
따라서 이 숫자는 **제품 숫자가 아니다.** 이긴 표현 위에서 기준선을 따로 잰다.

## 프로필 — 67개, 전부 기계 생성 (`eval/profiles.json`)
rule 29(장르 × 관심 수 3구간) · coh 10 · mix 12 · count 16. 내 판단이 들어간 시드 선택은 없다.

## 표본·채점
프로필·팔마다 **1-10 중 5 + 11-50 중 5**, RNG seed 1 고정. 슬롯 67 × 2 × 10 = 1,340. 팔 간 공유 쌍은 한 번만 채점.
합산 = 두 구간 단순 평균 (기존 관행). 적합 = 등급 ≥2 를 3역할 중 2 이상. 눈가림·셔플. **미채점 0 전에는 비교하지 않는다.**

### 채점 프롬프트 — 웹툰용으로 **문구까지 고정**한다. 이후 모든 웹툰 축에서 이 원문을 쓴다.
표준 3역할(X-15/X-16/X-24)에서 플랫폼 단어만 바꿨다. 인기 배제 지시는 **역할 A 에만** 있다(표준과 동일; X-22 처럼 B·C 에 넣지 않는다).

> **역할 A** — 당신은 추천 시스템의 품질 평가자입니다. 파일 {FILE} 을 읽으세요. 각 항목은 사용자가 좋아한 웹툰 시드 목록(seed)과 시스템이 추천한 웹툰 후보(cand, meta)입니다.
> 각 후보가 그 시드를 좋아하는 사용자에게 얼마나 관련 있는 추천인지 등급을 매기세요: 3 = 강한 적합 (시드와 장르·테마·톤이 명확히 맞음), 2 = 적합 (같은 계열, 자연스러운 추천), 1 = 약함 (겹치는 요소가 하나뿐이거나 결이 다름), 0 = 무관. 기준은 오직 시드와의 관련성입니다. 인기·평점은 보지 마세요. 모르는 작품은 제목·meta 로 추정하세요.
> 결과 JSON 한 줄 {"id": 등급, ...}(파일의 모든 항목)을 파일 {OUT} 에 저장하고, 최종 답변으로는 "저장 완료 N건"만 쓰세요.
>
> **역할 B** — 당신은 웹툰을 매우 많이 보는 헤비 독자입니다. 파일 {FILE} 을 읽으세요. 각 항목은 어떤 사용자가 좋아한 웹툰 시드 목록(seed)과 앱이 그 사용자에게 추천한 웹툰 후보(cand, meta)입니다.
> 당신이 그 시드들을 좋아하는 사람이라고 상상하고 "이 추천을 보면 실제로 눌러 볼까?"로 등급을 매기세요: 3 = 바로 볼 것 같다, 2 = 볼 만하다 (납득되는 추천), 1 = 굳이? (겹치는 게 하나뿐이거나 결이 다름), 0 = 왜 이게 나왔지. 모르는 작품은 제목·meta 로 추정하세요.
> 결과 JSON 한 줄 {"id": 등급, ...}(파일의 모든 항목)을 파일 {OUT} 에 저장하고, 최종 답변으로는 "저장 완료 N건"만 쓰세요.
>
> **역할 C** — 당신은 웹툰 플랫폼의 편집자/큐레이터입니다. 파일 {FILE} 을 읽으세요. 각 항목은 사용자가 좋아한 웹툰 시드 목록(seed)과 알고리즘이 추천한 웹툰 후보(cand, meta)입니다.
> "이 시드를 좋아하는 사용자에게 보여주는 추천 목록에 이 후보를 넣어도 편집자로서 부끄럽지 않은가"로 등급을 매기세요: 3 = 자신 있게 넣는다, 2 = 넣어도 된다, 1 = 넣기 애매하다 (겹치는 요소가 약하거나 톤·연령대 등 결이 다름), 0 = 빼야 한다. 모르는 작품은 제목·meta 로 추정하세요.
> 결과 JSON 한 줄 {"id": 등급, ...}(파일의 모든 항목)을 파일 {OUT} 에 저장하고, 최종 답변으로는 "저장 완료 N건"만 쓰세요.

`meta` 에는 장르·태그(최대 6)·회차 수만 넣는다. **관심 수·평점은 시트에 넣지 않는다** — 채점자가 인기를 볼 수 없게.

## 판정 (관측 전 고정) — 합산 기준
- **(A) rep_v2 채택**: rep_v2 − rep_v1 **≥ +0.03**
- **(C) rep_v1 채택**: rep_v1 − rep_v2 **≥ +0.03**
- **(B) 동률**(차이 < 0.03): **rep_v1 채택.** 단순한 쪽이다 — 태그 정지어 목록을 관리할 필요가 없고,
  게이트에서 장르 일치가 조금 높고 ILS 가 조금 낮았다. 동률 규칙을 관측 후에 정하지 않으려고 지금 적는다.
보조로 1-10/11-50 구간 · 축(rule/coh/mix/count)별 · ILS 를 낸다. 판정엔 쓰지 않는다.
