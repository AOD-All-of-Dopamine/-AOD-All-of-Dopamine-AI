세 저장소(AI·백엔드·프론트)와 **실제 배포본**을 대조해 확인한 것만 적는다. 추측은 "미확인"으로 표시한다.

- 고치는 방법의 상세는 `REC_TAB_DESIGN.md` **부록 D**(A/B/C 항목)에 있다. 추천 화면은 2026-09-26 **홈으로 합쳤다**(추천 탭 제거 — 프론트 설계 `2026-09-26-home-rec-only-design.md`). 여기서는 **무엇이 문제이고 지금 무엇이 막혀 있는지**만 본다.
- 보안 항목의 배경·절차는 **이 저장소에 두지 않는다**(공개 저장소). 별도 운영 메모를 본다.

## 0. 한 줄 요약

**추천 시스템이 서버에 올라가 있지 않다.** 그래서 로그인해도 개인화 추천이 아니라 인기 목록(대체)이 나온다.
추천기 자체와 백엔드 API·로그·프론트 화면은 **전부 준비돼 있다** — 빠진 것은 배포와 연결이다.

| 1 | 추천 엔진·라우터가 어디에도 배포돼 있지 않다 | 추천 | 확인됨 |

## 1. 추천 시스템이 배포돼 있지 않다  〔가장 큰 문제〕

**증상** — 로그인 사용자도 개인화 추천을 못 받는다. 응답이 `fallback:true` 로 온다.

**원인** — 백엔드가 부르는 추천 라우터가 없다.
- `RecRouterClient` 의 주소 기본값이 `http://localhost:18080` 인데, api 모듈에 **운영 설정 파일이 없다**(`application-local.properties`·`application-test.properties` 뿐).
- 그래서 요청 → 연결 실패 → 서킷 오픈 → 랭킹 대체. 기능 플래그(`rec.enabled`)는 기본 `true` 라 꺼져 있는 것이 아니다.

**준비된 것** — `recommendation/serving` 에 Dockerfile(`PLATFORM` 인자) · `compose.yaml`(엔진 4 + 라우터 1) · 헬스체크 · 메모리/CPU 확정값이 있다. 아티팩트 실제 용량은 Steam 2.7GB · TMDB 295MB · 웹소설 238MB · 웹툰 33MB.

**막힌 것** — 호스트(16GB·8vCPU 권장)와 설정 주입 방식(주소를 커밋하지 않고 환경변수로) 결정.

**참조** — `REC_TAB_DESIGN.md` §8-6 · §9 3~4단계 · `serving/README.md`

## 2. 로그인이 1시간마다 끊긴다

**증상** — 사용하다가 갑자기 대체 목록 + "로그인하면 취향 추천을 볼 수 있어요" 배너로 바뀐다.

**원인** — 토큰 수명 1시간, **갱신 수단 없음**. 만료되면 프론트가 401 을 받고 토큰을 지운다. 1시간 만료 자체는 정상이고, 문제는 활동 중에도 끊긴다는 것이다.

**영향이 큰 이유** — 추천·좋아요·싫어요가 전부 로그인 상태에서만 쌓인다. 이게 없으면 **아래 모든 작업이 한 시간짜리다.**

**참조** — §0-2 · 부록 D A2 (슬라이딩 세션 → 리프레시 토큰)

## 3. 인증 설정 정비

- JWT 서명 키를 환경변수로 옮기고 기동 시 검증한다(없거나 짧으면 기동 중단). 적용하면 전원 재로그인한다.
- 경로별 인증 정책을 정리한다(지금은 컨트롤러가 헤더를 직접 파싱한다).
- **상세·절차는 이 저장소에 두지 않는다** — 운영 메모 참조.
- **2026-09-24 기준 미조치.**

**참조** — §0-3 · 부록 D A1 · B10

## 5. 추천 탭 UI 가 설계와 어긋난다 — ✅ 해소 (2026-09-26)

**추천 탭(`/for-you`)을 없애고 추천을 홈 한 줄로 합쳤다**(프론트 #55 · 백엔드 #127, 운영 배포 확인).
- 홈 추천: 분야 칩 · 한 묶음 30개 가로 줄 · 순환 화살표 · 위치 표시 · **새 추천 받기**(같은 체인의 다음 쪽) — U5(배치 크기 · 새로고침)의 결정
- U1~U4(👎 표면 · 자리 유지 가려짐 · 라벨 · 엄지)는 홈 카드가 처음부터 설계대로라 추천 탭과 함께 닫혔다
- 옛 주소 `/for-you?tab=X` 는 `/home?rec=X` 로 넘어간다. 상단 메뉴 "추천" 삭제

**남은 것**: 엔진이 붙기 전까지 로그인 사용자는 인기 목록을 본다(1번). 전원 공개 전 **M6@30 오프라인 평가**(묶음 30은 평가된 M6@20 과 배분이 다르다 — 프론트 설계 "열린 결정 1").

**참조** — 프론트 `docs/superpowers/specs/2026-09-26-home-rec-only-design.md`(설계 · 검수 · 구현 기록) · REC_TAB_DESIGN §2-6 · §2-8

## 6. 추천 정확성 3건

| | 문제 | 왜 배포 전에 |
|---|---|---|
| 6-1 (A5) ✅ 해결 `2c0b06b` | 라우터가 `k+buffer`(50)로 M6 를 섞고 상위 20 만 쓴다 | M6 쿼터는 k 의 함수라 **평가된 배분과 다른 목록**이 나간다. 올린 뒤 고치면 변화 원인을 못 가린다 |
| 6-2 (A7) | 서빙 가능 목록(카탈로그)이 연결돼 있지 않다 | 끄면 DB 에 없는 작품이 후보에 섞여 20개를 못 채우고, **켜면 순위가 바뀐다** — 사전등록 판정 여부를 먼저 정해야 한다 |
| 6-3 (A6) | Steam 동일성 기준에 `k=30`·`seen` 누적 사례가 없다 | 후처리를 크게 고쳤는데 그 경로를 검증하는 기준이 없다 |

## 7. 관측 지표가 없다

- 로그 파이프라인 지표 4종(`rec.log.written`·`dropped`·`duplicates`·`failed`)과 큐 게이지만 있다.
- **대체 비율 · 부분 응답 · 지연 p95 · 이벤트 건수 · 거절 비율에는 대응 지표가 없다.** §11 경보표의 대부분을 지금은 켤 수 없다.
- 그래서 "추천이 이상하다"를 **사용자가 먼저 알았다**(2026-09-22). `fallbackReason` 분포만 대시보드에 있었으면 즉시 보였다.
- **미확인**: 운영 DB 에 로그가 실제로 쌓이는지. 적재가 비동기라 응답이 정상이어도 보장되지 않는다 — §5-10 의 확인 SQL 한 번이면 끝난다.

**참조** — §5-10 · §11 · 부록 D B15

## 8. 배포 구성 불일치

| | 문제 | 위험 |
|---|---|---|
| 8-1 | 프론트 `apps/web/.env.production` 은 `VITE_API_BASE_URL=/api` 인데 **실제 배포본은 절대 URL** 을 쓴다 (Vercel 환경변수가 덮어씀). `vercel.json` 에 `/api` 리라이트도 없다 | 저장소 기본값대로 빌드하면 **API 호출이 SPA HTML 로 떨어진다**. Vercel 설정 확인 전에는 이 파일을 건드리면 안 된다 |
| 8-2 | 부하 관문이 개발 PC 기준 — Steam 시드 50·동시 5 에서 p95 1825ms 미달 | 실제 호스트에서 다시 재야 §9 3단계 완료 조건을 판정할 수 있다 (A10) |
| 8-3 | 프론트 `develop` 이 `main` 보다 **312 커밋 뒤처짐** | 실수로 develop 기준으로 작업하면 대량 충돌. 정리하거나 폐기 결정 필요 |
| 8-4 | 라우터 `/health` 가 엔진이 전멸해도 200 | compose 헬스체크로 장애를 못 잡는다 (B7) |

## 9. 문서·코드 동기화

- `aod_rec.corpus_map` 테이블은 **스키마만 있고 아무도 읽지 않는다** — 실제 키 변환은 `CorpusKeyService` 가 `platform_data.platform_specific_id` 로 즉석 처리한다. 살릴지 지울지 정해야 한다(B19).
- 2026-09-23 검수에서 설계 문서의 사실 오류 8건을 고쳤다(지표명·컴포넌트명·buffer·삭제 주기·중복 판정·Content-Type·payload 키·`reason.type`). 백엔드를 바꿀 때 문서를 같이 고치지 않으면 같은 일이 반복된다(B20).
